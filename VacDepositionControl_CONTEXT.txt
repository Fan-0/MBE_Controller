SECTION 2: HARDWARE — HEAT3 DUAL-MODE HEATING POWER SUPPLY
================================================================================

MANUFACTURER: Prevac
PROTOCOL:     Modbus RTU over RS-485
BAUD:         19200, 8N1  (was 57600 in earlier config — confirmed 19200 on lab unit)
SLAVE ID:     1
SERIAL TIMEOUT: 0.25s  (was 1.0s — reduced for speed)
RESPONSE BYTES:  read exactly `expected` bytes — NOT max(expected,8) which caused 0.25s
                 timeout on every 7-byte response (1-register FC 0x03 reads)
TRANSACT SLEEP: 0.01s after write, before read (was 0.04s — RS-485 turnaround headroom)
INTER-WRITE SLEEP: 0.01s between two 16-bit words of an INT32 (fallback FC 0x06×2 path)
READBACK DELAY:    0.30s after writing setpoint before verify read

CHANNEL ASSIGNMENT:
  CH1 = Selenium (Se) evaporation source
  CH2 = Substrate heater

TEMPERATURE ENCODING (critical):
  All temp registers = INT32, unit = Kelvin × 100 (signed)
  raw → °C:  raw / 100.0 - 273.15
  °C → raw:  round((°C + 273.15) * 100)
  INT32 split into TWO consecutive 16-bit registers:
    reg N   = high word (MSW)
    reg N+1 = low word  (LSW)
  WRITE METHOD: two separate FC 0x06 single-register writes (NOT FC 0x10)
  REASON: Some HEAT3 firmware returns non-standard FC 0x10 responses

MODBUS FUNCTION CODES USED:
  FC 0x03  read holding registers (response: 3 + n*2 + 2 bytes)
  FC 0x06  write single register  (response: 8 bytes = echo of request)
  FC 0x10  NOT USED (firmware compatibility issue)

CRC: CRC-16 Modbus (polynomial 0xA001), appended little-endian

EXCEPTION FRAME: 5 bytes (addr, FC|0x80, error_code, CRC×2)
  Codes: 1=illegal fn, 2=illegal addr, 3=illegal data, 4=device error, 5=busy

REGISTER MAP — CH1 (Selenium):
  R_STATUS1    =  0   INT16 R   bit0=OPERATE state, bit3=no TC1, bit4=no TC2
  R_PID_ST1    =  1   UINT8 R   0=Off, 1=Run, 2=Hold
  R_PV1        =  2   INT32 R   process value (current temp), regs 2–3
  R_TC1        =  4   INT32 R   thermocouple TC1, regs 4–5
  R_TC2        =  6   INT32 R   thermocouple TC2, regs 6–7
  R_SP1        = 14   INT32 R/W PID setpoint (T mode), regs 14–15; INT32 K×100
  R_WMODE1     = 21   UINT8 R/W 0=Manual,1=Auto,2=External(RO),3=PIDOut(RO)
  R_OP1        = 70   UINT8 W   write 1 → enter OPERATE state
  R_STBY1      = 71   UINT8 W   write 1 → enter STANDBY state
  R_PIDRUN1    = 72   UINT8 W   write 1 → start PID regulation
  R_PIDHOLD1   = 73   UINT8 W   write 1 → hold PID
  R_RAMP1      = 43   INT16 R/W PID SP ramp rate; stored as rate×10 in R_RAMP_UNIT1 units
  R_RAMP_UNIT1 = 44   UINT8 R/W ramp unit: 0=per/s, 1=per/min, 2=per/h
  R_OUT1       = 151  INT16 R   PID output % (value × 100 = %)
  R_WATTS1     = 248  INT16 R   output power (value × 100 = W)

REGISTER MAP — CH2 (Substrate):
  R_STATUS2    = 84   INT16 R   same bit layout as STATUS1
  R_PID_ST2    = 87   UINT8 R
  R_PV2        = 88   INT32 R   regs 88–89
  R_SP2        = 90   INT32 R/W regs 90–91
  R_WMODE2     = 97   UINT8 R/W same values as WMODE1
  R_OP2        = 114  UINT8 W   write 1 → OPERATE
  R_STBY2      = 115  UINT8 W   write 1 → STANDBY
  R_PIDRUN2    = 116  UINT8 W   write 1 → PID RUN
  R_PIDHOLD2   = 117  UINT8 W   write 1 → PID HOLD
  R_RAMP2      = 101  INT16 R/W PID SP ramp rate for CH2 (**); same encoding as R_RAMP1
  R_RAMP_UNIT2 = 102  UINT8 R/W ramp unit for CH2: 0=per/s, 1=per/min, 2=per/h
  R_OUT2       = 153  INT16 R   PID output %
  R_WATTS2     = 249  INT16 R   output power

DEVICE-INTERNAL SP RAMP RATE (regs 43/44 CH1, 101/102 CH2):
  Controls how fast HEAT3 transitions to a newly written SP internally.
  Encoding:  stored_value = actual_rate × 10  (e.g. 4 °C/min → write 40)
  Unit reg:  0 = per/s, 1 = per/min (always write 1), 2 = per/h
  0 = instant (ramping disabled — SP jumps immediately).
  Factory defaults: CH1(Se) = 4 °C/min (stored 40), CH2(Sub) = 100 °C/min (stored 1000).
  API: heat3.read_ramp_rate(ch) → float °C/min
       heat3.write_ramp_rate(ch, rate_per_min) → bool
  GUI: "Dev Ramp" spinbox + "Set" button on each TempCh panel.
       Spinboxes are auto-populated when HEAT3 connects (or test mode activates).

REGISTER MAP — GLOBAL:
  R_REMOTE   = 1000 UINT8 R    read-only mirror of REMOTE state (writes ACK'd but ignored)
  R_REM_EN   = 1151 UINT8 R    1 = Remote Enable is ON in device menu

REMOTE MASTER PROTOCOL (confirmed by diagnostics 2026-05-06):
  REQUIRED PREREQUISITE: Set Remote Enable ON from device front panel:
    Settings → Communication → Remote Enable → ON
    (Software CANNOT enable this remotely)
  R_REMOTE (reg 1000) IS READ-ONLY on this firmware.
    Writing 1 to it is ACK'd but has no effect — reg stays 0.
    Modbus writes (SP, WMODE, OPERATE etc.) work regardless of reg 1000.
  MAINTAIN:  send ANY Modbus frame within 10s (device drops REMOTE after 10s silence)
             The 0.5s poller's FC 0x03 reads are sufficient keepalive.
  DO NOT WRITE reg 1000 = 0 on disconnect — on some firmware this permanently
    disables Remote Enable in the device settings (requires front-panel fix).

APPLY SETPOINT SEQUENCE (apply_setpoint(ch, celsius)):
  1. write 1 → WMODE[ch]           (ensure Auto mode)
  2. sleep 0.02s
  3. write INT32 → SP[ch]          (FC 0x10 preferred, FC 0x06×2 fallback)
  4. sleep 0.30s                   (device latches SP before readback)
  5. read SP[ch] back, verify |readback - target| < 1°C
  Returns: {"ok": bool, "readback": float|None, "message": str}

GO OPERATE SEQUENCE (go_operate(ch)):
  write WMODE[ch]=1 → OP[ch]=1 → PIDRUN[ch]=1
  read STATUS[ch] bit0 to confirm OPERATE state
  Returns: {"ok": bool, "message": str}

GO STANDBY (go_standby(ch)):
  write STBY[ch]=1
  Returns: {"ok": bool, "message": str}

BATCH POLL (poll_all()) — used by Poller for speed:
  Read 1: CH1 regs 0–21  (22 words, 1 FC 0x03) → STATUS1, PV1, SP1
  Read 2: CH2 regs 84–97 (14 words, 1 FC 0x03) → STATUS2, PV2, SP2
  Read 3: regs 151–153   ( 3 words, 1 FC 0x03) → R_OUT1, R_OUT2
  Returns dict: {ch1_pv, ch1_sp, ch1_op, ch1_out, ch2_pv, ch2_sp, ch2_op, ch2_out}
  3 transactions vs 8 individual reads → ~4× faster poller cycle
  IMPLEMENTED in heat3.py; Poller in gui_app.py uses hasattr(h,'poll_all') guard
  HEAT3Sim does NOT implement poll_all() — Poller falls back to individual reads for sim

THREADING LOCKS IN HEAT3 DRIVER:
  _port_lock  (Lock): one Modbus transaction at a time (low level)
  _seq_lock   (Lock): held for entire multi-step sequences (apply_setpoint, go_operate)
  _safe_read acquires _seq_lock with timeout=0.15s before individual reads
  Heartbeat acquires _seq_lock non-blocking (skip if sequence in progress)

DEBUG: heat3.debug_callback = callable(str) → receives "TX: XX XX XX" / "RX: XX XX XX"

SECTION 3: HARDWARE — B-RAX 3400 VACUUM GAUGE (InstruTech)
================================================================================

MANUFACTURER: InstruTech
SENSORS:      Ion Gauge (IG) + Convectron CG1 + Convectron CG2 + Analog Input
PROTOCOL:     InstruTech RS-485 ASCII (COMM Type = RS485)
BAUD:         19200, 8N1
ADDRESS:      01 (hex, 00–FF, factory default = 01, configurable)
DEFAULT PORT: COM3 since 2026-10-21 (was COM11, Prolific PL2303GT — Section 13)
              NOTE: was incorrectly assumed COM9; use serial.tools.list_ports to discover
SERIAL TIMEOUT: 0.25s  (was 1.0s — reduced for speed)
COMMAND SLEEP:  0.02s after write, before read_until (was 0.06s)
RESPONSE TERM:  \r  (carriage return, NOT \n) — use read_until(b'\r') not readline()
                readline() waits for \n and always times out on BRAX responses

FRAME FORMAT:
  Command:  #AA<CMD>\r    (AA = 2-char hex address, e.g. "01")
  Response: *AA <value>\r (13 chars total including \r, fixed-length)
  Error:    ?AA <error>\r  (invalid cmd or out-of-range)

RESPONSE PARSING (_parse_pressure):
  Strip leading '*', skip 3 chars (2-char address + space), float(remainder)
  Returns None for responses starting with '?' or '!'
  Example: "*01 1.53E-06\r" → strip '*' → "01 1.53E-06" → skip 3 → "1.53E-06" → 1.53e-6

KEY COMMANDS:
  #01RDIG\r   read ion gauge pressure (Torr)
              returns 1.10E+03 if IG off or sensor disconnected
  #01RDCG1\r  read convectron gauge 1
  #01RDCG2\r  read convectron gauge 2
  #01RDAI\r   read analog input
  #01IG1\r    turn IG ON  → response: "*01 PROGM_OK\r"
  #01IG0\r    turn IG OFF (also clears IG error flags)
  #01IGS\r    query IG state → "*01 1 IG_ON \r" or "*01 0 IG_OFF\r"
  #01RSIG\r   IG diagnostic: 00=OK, 01=OVPRS, 02=EMISS, 04=FLVLO,
              08=FLOPN, 10=DEGAS, 20=ICLOW, 40=FLIHI
  #01DG1\r    start IG degas (requires IG on, P < 5e-5 Torr)
  #01DG0\r    stop IG degas
  #01DGS\r    query degas state
  #01VER\r    firmware version

IG INTERLOCK: Cannot enable IG if P > 1e-3 Torr (100µA emission) or 5e-4 Torr (4mA)
              Send #01IG0\r first to clear error flags, then #01IG1\r

SECTION 4b: HARDWARE — EUROTHERM EPC3004 INDIUM SOURCE CONTROLLER
================================================================================

MANUFACTURER: Eurotherm (Schneider Electric)
PURPOSE:      Single-loop PID temperature controller for the Indium evaporation source
PROTOCOL:     Modbus RTU over RS-485
BAUD:         19200, 8N1
SLAVE ID:     1 (configurable)
DEFAULT PORT: COM7 since 2026-10-21 (was COM13; configurable in Settings / DCFG)

THERMOCOUPLE TYPE: Type C (W5%Re / W26%Re, ASTM E988), 0–2315°C
  The EPC3004 does not natively support Type C.
  SOLUTION: J-PROXY METHOD — EPC3004 configured as Type J TC; Python corrects PV/SP.
  Status: CONFIRMED WORKING (2026-05-13)

J-PROXY METHOD — HOW IT WORKS:
  1. EPC3004 is configured: AI.1.Type=0 (Thermocouple), AI.1.Linearisation=0 (J).
     One-time setup: run  python diagnostics/configure_epc3004_cstm1.py --port COM13 --set-j-mode
  2. The Type C TC generates EMF V_C(T_true). The EPC3004 treats this as Type J EMF:
       V_eff = V_C(T_true) + Δ_CJC   where Δ_CJC = V_J(25°C) − V_C(25°C) = +0.924 mV
       T_J_display = J_inverse(V_eff)   → displayed in range ~18–679°C
  3. Python converts in both directions via 16-point piecewise-linear tables:
       j_display_to_c(t_j) → true Type C °C  (used when reading PV)
       c_to_j_display(t_c) → J-apparent °C   (used when writing SP)
  4. The EPC3004 instantiation in gui_app.py uses j_proxy=True:
       EPC3004(port, id, baud, j_proxy=True)
     With j_proxy=True, _raw_to_c() and _c_to_raw() apply the conversion transparently.
     All external interfaces (GUI labels, recipe engine, safety checks) see true °C.

    17.9              →    0.0
    45.9              →  100.0
    76.6              →  200.0

J-PROXY CONFIRMED REGISTER ADDRESSES (from iTools addys.csv, 2026-05-12):
  AI.1.Type          frame 0x3002  (iTools Comms 0x00033002 → low 16 bits)
    enum: 0=Thermocouple, 1=mV, 2=V, 3=mA, 4=RTD, 5=Zirconia
    J-proxy mode: write 0 (Thermocouple)
  AI.1.Linearisation frame 0x078E  (iTools Comms 0x0003078E → low 16 bits)
    enum: 0=J, 1=K, 2=L, 3=R, 4=B, 5=N, 6=T, 7=S, 8=Custom1, 9=Custom2…
    J-proxy mode: write 0 (J)
  NOTE: Custom1 (LIN16/CSTM1) breakpoint registers were NOT found in the iTools
    address-space export — they are hidden until Custom1 is activated in iTools.
    The J-proxy approach was chosen because it requires only the two confirmed registers.

CHANNEL ASSIGNMENT:
  CH1 = Indium evaporation source (single channel device — only CH1 exists)

TEMPERATURE ENCODING:
  RESOLUTION_FACTOR = 10 (confirmed by diagnostic 2026-05-11)
  Device display is configured for 0.1°C resolution (one decimal place).
  raw → °C (device scale):  raw / 10.0   (e.g. raw 2000 = 200.0°C in J-scale)
  With j_proxy=True: _raw_to_c() further applies j_display_to_c() → true Type C °C
  With j_proxy=True: _c_to_raw() applies c_to_j_display() before ×10 encode
  All PV/SP registers are INT16 (signed).

KEY MODBUS REGISTERS (confirmed by epc3004_diag.py, 2026-05-11):

  Frame addr  iTools#  Type   R/W  Description
  ──────────────────────────────────────────────────────────────────────────────
  0x0001      1        INT16  R    R_PV: Process Variable (current temp, °C×10)
  0x0002      2        INT16  R    R_SP_RO: Working Setpoint — READ-ONLY
                                   Tracks target SP through the ramp limiter.
                                   Write returns Modbus exception code 2.
                                   Used for live display in poll_all() (in_sp key).
  0x0004      4        INT16  R    R_OP: Working Output Power (raw ÷ 10 = %)
                                   Confirmed ~375 = 37.5% at 200°C.
  0x0005      5        INT16  R    R_WSP: Working Setpoint (same as R_SP_RO)
  0x0018      24       INT16  R/W  R_SP: Target Setpoint 1 — WRITABLE
                                   Write here to command a new SP; device ramps
                                   R_SP_RO toward R_SP at the configured rate.
                                   Confirmed writable by write+readback test.
  0x0020      32       INT16  R/W  R_SP_RATE: SP Ramp Rate (stored as rate × 10)
                                   Confirmed readable: raw 1000 = 100.0°C/min.
                                   Write access not yet confirmed (test with iTools).
  0x0021      33       INT16  R/W  R_SP_RATE_U: SP Rate Unit
                                   0=off (instant), 1=°C/s, 2=°C/min, 3=°C/h
                                   Confirmed readable: 0 = ramp currently disabled.
  0x0111      273      UINT16 R    R_STATUS: Instrument Status word
                                   bit 0 = Summary alarm; bit 3 = sensor break
                                   bit 8 = Manual mode (0=Auto, 1=Manual)
                                   Confirmed readable: 0x0000 = Auto, no alarms.
  0x0112      274      UINT16 R/W  R_AUTO_MAN: Auto/Manual switch
                                   0 = Auto (PID running), 1 = Manual (output off)
                                   Confirmed readable; write not yet confirmed.

  REGISTER ADDRESSES THAT DO NOT WORK (confirmed by diagnostic):
  0x0002 is READ-ONLY despite being listed as R/W in some reference docs.
  0x0023 / 0x0024 (old driver guess for ramp regs) return 0x8000 sentinel —
    not applicable on this firmware. Correct addresses are 0x0020 / 0x0021.

DRIVER API (devices/epc3004.py):
  EPC3004(port, slave_id=1, baudrate=19200, j_proxy=False)
    j_proxy=True: enables Type C J-proxy conversion in _raw_to_c() / _c_to_raw().
    gui_app.py instantiates with j_proxy=True (as of 2026-05-13).

  Module-level conversion functions (also importable):
    j_display_to_c(t_j)  → float   J-apparent °C → true Type C °C
    c_to_j_display(t_c)  → float   true Type C °C → J-apparent °C (for SP writes)

  connect()                          → bool (raises ConnectionError on failure)
  disconnect()                       → None
  connected: bool                    class attr, True after connect()
  j_proxy: bool                      True = J-proxy mode active (Type C via Type J)
  poll_all()                         → {"in_pv": float, "in_sp": float,
                                         "in_op": bool, "in_out": float}
                                       in_pv/in_sp are in TRUE TYPE C °C when j_proxy=True.
  apply_setpoint(ch, celsius)        → {"ok": bool, "readback": float, "message": str}
                                       celsius is TRUE TYPE C °C when j_proxy=True.
                                       Writes to R_SP (0x0018); reads back from same.
  go_operate(ch=1)                   → {"ok": bool, "message": str}
  go_standby(ch=1)                   → {"ok": bool, "message": str}
  read_ramp_rate(ch)                 → float (°C/min); reads R_SP_RATE 0x0020
  write_ramp_rate(ch, rate_per_min)  → bool; writes R_SP_RATE 0x0020 + R_SP_RATE_U 0x0021

KEY DESIGN PATTERNS:

1. SINGLE SERIAL READ PATH (critical — eliminates port contention):
   Poller thread → reads all hardware → Snap.write(**d) AND logger.feed(ig, ch1, ch2)
   DataLogger has NO internal poll thread; it is purely a buffer + CSV writer.
   logger.feed() is the ONLY way data enters the plot buffers during live logging.
   During recipe runs, _sync_rec_log() pushes rec_log rows into the same buffers.

2. HARDWARE SNAPSHOT (no serial I/O on main thread):
   Poller thread (0.25s default) → reads hardware → Snap.write(**d)
   self._vt QTimer (100ms)       → Snap.read() → updates value labels
   Snap is a thread-safe dict (Lock-guarded)

3. PLOT PIPELINE:
   Poller._loop() → logger.feed()       → pressure_buf / ch1_temp_buf / ch2_temp_buf / in_temp_buf
   PlotWorker QThread (100ms tick)       → reads buffers, filters to rolling window,
                                           builds numpy arrays, emits data_ready signal
   MainWindow._on_plot_data(d) slot      → setData() on pyqtgraph PlotDataItems (tc1/tc2/tc3)
                                           + setXRange(x_min, x_max) for rolling window
   Temperature curves: tc1=Se(OR), tc2=Sub(PU), tc3=In(IN_C cyan)

   Buffer timestamps: absolute Unix float (time.time()) — DateAxisItem shows wall clock.

   PlotWorker.window_s: rolling window length in seconds; set by _set_plot_window().
   Window options: 60 / 600 / 1800 / 3600 s (buttons in plot tab, default 600).

   CRITICAL — x-range must advance every tick:
   PlotWorker._tick() always computes x_min/x_max BEFORE the data-change early-return.
   If no new data: emits {'x_min': cutoff, 'x_max': now} only (no arrays).
   If new data:    emits full dict with arrays + x_min/x_max.
   This ensures setXRange is called every 100ms even with no new data, so the rolling
   window advances continuously. Without this, the view froze and new data appeared
   off-screen to the right, then "rolled in" as the window eventually caught up.

4. POLLER BATCHING:
   if hasattr(heat3, 'poll_all'):     # real HEAT3 → 3 batch Modbus reads
       d.update(heat3.poll_all())
   else:                              # HEAT3Sim → 8 individual attribute reads
       individual reads per channel
   if hasattr(epc, 'poll_all'):       # EPC3004 → poll_all() → in_pv/sp/op/out
       d.update(epc.poll_all())
   else:
       individual reads: in_pv, in_sp, in_out, in_op
   After reads: self.snap.write(**d) AND if self.logger: self.logger.feed(ig, ch1_pv, ch2_pv, in_pv)

5. PLOT SYNC DURING RECIPE RUNS:
   _sync_rec_log() QTimer (100ms) reads NEW rows from rec_log._rows_pressure/temp.
   Uses _sync_p_idx / _sync_t_idx (MainWindow attrs) to track last synced position.
   Only rows[idx:] are appended — each row is pushed to logger buffers exactly once.
   Indices reset to 0 at run start (_r_run) and when rec_log.running is False.
   Converts elapsed time to absolute timestamp: base = now - last_elapsed (of entire list)
   Appends (base + elapsed, value) tuples to logger buffers.
   PlotWorker picks up the new tail on its next 100ms tick.

   CRITICAL — do NOT re-append all rows on every tick:
   Old code used rows[-20:] on every call → same row appended ~10× per second at 1Hz
   rec_log rate → 10× duplicate points on the plot (visually: thick stacked traces).
   Fix: index-tracked append (rows[_sync_p_idx:]) ensures one append per new row.

  start()   clear _stop, _loop_counters; start _run thread
  pause()   clear _pause Event → _wait() blocks
  resume()  set _pause Event
  stop()    set _stop + _pause; ALSO calls bep.abort() (a MEASURE_BEP step blocks the
            recipe thread inside the sweep — aborting closes the shutters and drops out
            of the 20 Hz sampling loops so the 3 s join() can succeed); join thread 3s;
            state→IDLE
  load_excel(path) → List[RecipeStep]

_run() LOOP LOGIC:
  idx = 0
  while idx < len(steps):
    if _stop: break
    _pause.wait()
    result = _exec(step, idx)
    if result is None:  → STATE_ERROR, return
    elif result == -1:  → idx = _goto_idx   (GOTO jump)
    elif result == 2:   → break              (END clean exit)
    else:               → idx += 1
  if not _stop.is_set(): → STATE_DONE
  (this ensures END→DONE and stop()→IDLE, never confused)

_exec() RETURN VALUES:
  1    normal advance
  -1   GOTO jump (self._goto_idx set to target row index)
  2    END clean exit
  None error (caller sets STATE_ERROR)

ACTION IMPLEMENTATIONS:

SET_TEMP:
  if _is_indium_src(p1) → self.indium.apply_setpoint(1, float(p2)); return 1 early
  elif p1 is alpha str  → ch = _src_to_ch(p1), temp = float(p2)
  else                  → ch = 1, temp = float(p1)   (legacy)
  heat3.apply_setpoint(ch, temp)

RAMP_TEMP:
  p1 = channel (Selenium/Substrate/Indium), p2 = rate °C/min
  if _is_indium_src(p1) → self.indium.write_ramp_rate(1, rate); return 1
  else                  → heat3.write_ramp_rate(_src_to_ch(p1), rate)
  Sets the device-internal ramp rate. Equivalent to "Dev Ramp → Set" in TempCh panel.
  No software stepping, no target SP — use SET_TEMP afterward to move to new target.
  Typical recipe pattern: RAMP_TEMP (set rate) → SET_TEMP (set target) → WAIT_TEMP (stabilize).
  If device is None: logs warning and skips (return 1), no error.
  BUG HISTORY (fixed 2026-05-09): Old RAMP_TEMP did software stepping (step SP every 5s
    toward target). Replaced with device-internal ramp to avoid setpoint churning and
    correctly match GUI behavior. Old 6-col recipes had (channel, target, rate) in
    (p1, p2, p3); new behavior ignores old p3 and uses p2 as the rate.

INCREASE_TEMP:   (added 2026-09 — for flux-calibration staircases)
  p1 = channel (Selenium/Substrate/Indium), p2 = Δ°C (negative steps down)
  Reads the CURRENT SETPOINT, adds p2, writes it back via apply_setpoint:
    Indium → indium.ch1_read_setpoint() (falls back to ch1_read_process_value())
    HEAT3  → getattr(heat3, f"ch{ch}_read_setpoint") (falls back to the PV reader)
  WHY SETPOINT-RELATIVE, NOT PV-RELATIVE: a calibration loop runs this once per pass;
    stepping from the SP lands on exact repeatable temperatures, whereas stepping from
    the live PV would accumulate drift every pass if the source has not fully settled.
  Missing p2 → returns None (ERROR). Missing device → logs warning, returns 1 (skip).
  Unreadable setpoint → returns None (ERROR) rather than guessing a base.

MEASURE_BEP:     (added 2026-09)
  p1 = "In" | "Se" | "Both"   (p2 unused)
  if self.bep is None → logs warning, returns 1 (skip)
  Calls bep.measure_sync(src, should_stop=lambda: self._stop.is_set()) — BLOCKS the
    recipe thread for the whole sweep (~10 s per source, ~50 s for Both incl. settle),
    which is the point: the next step must not start before the flux point is taken.
  Logs each record, then fires on_bep_result([(rec, trace), …]) ONCE for the step.
  Opens the shutter(s) it measures — do not place one inside a window where the
    shutter must stay in a particular state.
  Typical calibration pattern:
    RAMP_TEMP → SET_TEMP → [WAIT_TEMP → MEASURE_BEP → INCREASE_TEMP → GOTO] → HEATER_OFF

RHEED_VIDEO:     (added 2026-10-21 — roadmap R14)
  p1 = clip length in seconds (0 = one still PNG); p2 unused. Missing/bad p1 → None (ERROR).
  Calls the GUI hook engine.rheed_capture(duration, step_no, should_stop) — set by
    MainWindow.__init__ to _rheed_recipe_capture. Hook None, or no camera connected on
    the 📡 RHEED tab → logs ⚠ and returns 1 (SKIP — a missing camera never aborts a run).
  BLOCKS the recipe thread for the clip (like WAIT_TIME): the recipe is paused at that
    point with everything held; the preview timeline counts p1 seconds. Recipe Stop ends
    the clip early (partial clip kept).
  Uses the RHEED tab's CURRENT camera/source and its resolution/format ("the settings on
    the RHEED tab"). Sample = the name given to the RUN (rec_log.sample_name), NOT the
    RHEED tab's Sample box (user, 2026-10-21).
  FILES  <LOG_ROOT>/rheed/<run name>/<sample>_Sub<T>C_SeIn<ratio>_rheed_<NNN>.avi|.png
                                    + same-name .txt (metadata)
    <run name> = rec_log.run_name = <run START stamp>_<sample> — the run .xlsx now uses
      the same name (it was stamped at export time before).
    T = last CH2 (substrate) PV from the DataLogger buffers at the clip start ("SubNA"
      if none); ratio = bep.se_in_ratio, the LAST Se/In BEP measurement ("SeInNA").
    NNN = per-run counter MainWindow._rheed_n (reset in _r_run) — counts up on every
      execution, so GOTO loops give _001, _002, … and never overwrite.
  RECORDING: rheed.capture.record_clip(source, path, duration, should_stop) — blocking,

    size and deletes the local copy; on failure the files stay local + ⚠ in the log.
    (A ~12 MB/s stream written straight onto Box Drive could stall → dropped frames.)
  METADATA .txt: sample, run, step, clip #, start/end (ms), length, camera (source,
    WxH, codec, frames, measured fps, dropped), substrate T at start, Se/In ratio + In/Se
    BEP, setpoints (Se CH1, Sub CH2, In EPC) + shutter states at start AND end, min /
    mean / max per column over the clip, then the time series (DataLogger buffers,
    ~4 Hz: Timestamp, Elapsed_s, IG_Pressure_Torr, CH1_Se_C, CH2_Sub_C, In_C) for

  RUN LOG: rec_log.add_rheed_clip({...}) → sheet "RHEED clips" in the run .xlsx (#, step,
    run elapsed, start, length, frames, Sub T, Se/In ratio, file, metadata, folder).
  Tested 2026-10-21 (Test mode + simulated camera, offscreen): SET_TEMP → RHEED_VIDEO 3 →

WAIT_TEMP:
  p1 = channel name (e.g. "Selenium (CH1)", "Substrate (CH2)", "Indium (EPC)") OR legacy float
  p2 = tolerance °C (default 2.5)
  if _is_indium_src(p1) → reads PV from self.indium.ch1_read_process_value()
  elif alpha string      → reads PV from heat3.ch{n}_read_process_value()
  else (legacy float)   → reads PV from heat3.ch1_read_process_value()
  Explicit device check at entry: if device is None, logs warning and skips (return 1).
    This makes missing-device skip visible in the log rather than a silent 2s pass-through.
  Logs initial state at entry: "WAIT_TEMP CH1(Se): SP=X°C  PV=Y°C  tol=±2.5°C  hold=15s"
  Stability requirement: PV must reach SP first, then stay within ±tol for 15 continuous seconds.
  Poll every 2s (time.monotonic() for stable_since — more robust than time.time()).
  If |PV-SP| ≤ tol: start stable_since timer, log "reached X°C — holding for 15s…"
  If PV drifts out of range: log "left range — stability reset", reset stable_since to None.
  Progress update logged every 6s during the hold window.
  Break (advance recipe) only when elapsed >= 15.0s and continuously in range.
  _r_run() logs "▶ Run: heat3=<type>  test=ON/OFF" so device assignment is always visible.
  NOTE: p1 now selects the channel — previously was hardcoded to CH1 (BUG FIXED)

WAIT_PRESSURE:
  poll every 2s: read brax.read_ion_gauge(), break if P ≤ float(p1)

WAIT_TIME:
  _wait(float(p1))  — respects pause/stop, sleeps in 0.25s increments

OPEN_SHUTTER / CLOSE_SHUTTER:
  p1 lower: "both" → both_open/close; "se" → se_open/close; else → in_open/close

HEATER_ON:  if _is_indium_src(p1) → indium.go_operate(1)  else → heat3.go_operate(_src_to_ch(p1))
HEATER_OFF: if _is_indium_src(p1) → indium.go_standby(1) else → heat3.go_standby(_src_to_ch(p1))

GOTO:
  target = int(p1)  loops = int(p2)
  find target step index by step number
  _loop_counters[idx] initialized to loops on first hit
  if counter > 0: decrement, jump; if 0: del counter, fall through
  NET: steps execute (loops+1) total times

_src_to_ch(param) → int:
  "se", "selen", "1" → 1
  "sub", "substrate", "2" → 2
  default → 1

_is_indium_src(param) → bool:
  True if "indium" or "epc" in str(param).lower()
  SAFE: "Selenium" has no "indium"/"epc"; "Substrate" has no "indium"/"epc" → no false matches
  Used to route Indium actions to self.indium (EPC3004) before _src_to_ch fallback

SECTION 8: SOFTWARE — BEP MANAGER (bep_manager.py)
================================================================================

CLASS: BEPManager
PURPOSE: Beam Equivalent Pressure measurement for flux calibration

CONSTANTS:
  OPEN_DURATION     = 2.0 s     (shutter open time)
  FAST_INTERVAL     = 0.05 s    (20 Hz sampling)
  BASELINE_DURATION = 8.0 s     (baseline averaging window)
  SETTLE_TIME       = 30.0 s    (post-In wait before Se measurement)
  TOP_FRACTION      = 0.5       (top 50% of open-window samples used for BEP mean)
  NOTE: bep_manager.py imports ONLY stdlib (csv/os/time/threading/statistics/datetime/
  typing), so recipe_editor.py safely imports these timing constants while staying
  hardware-free. Keep it that way — adding a serial/PyQt import here would break the
  standalone editor's build.

ENTRY POINTS — two, with different threading models:
  start_measurement()                     → spawns the "BEP" thread, runs _run()
                                            (In → settle → Se). Used by the BEP tab.
  measure_sync(source="Both", should_stop=None) → List[BEPRecord]   (added 2026-09)
    Runs on the CALLING thread and BLOCKS. Used by the recipe engine's MEASURE_BEP so a
    step waits for its flux point instead of racing past it.
    source: "In" | "Se" | "Both" (anything unrecognised falls back to both).
      Guard: a literal "Selenium" contains the substring "in", so the matcher explicitly
      clears want_in when "selen" is present.
    Skips with a log line when self.shutter is None, or when the async thread is live.
    Clears _stop on entry; polls should_stop between phases; mid-sweep interruption goes
    through abort() (which RecipeEngine.stop() calls).
    Fires on_complete when it produced records, so the BEP tab plots refresh.
  trace_for(source) → BEPTrace | None     — latest trace_in / trace_se by name.

MEASUREMENT SEQUENCE:
  Phase          Duration  Sampling  Action
  ─────────────────────────────────────────────────────────────────
  Baseline(In)   8s        20Hz      shutter closed, accumulate baseline samples
  Open In        2s        20Hz      in_open(), accumulate in fast_buf + trace
  Close In       —         —         in_close()
  Settle         30s       —         wait for chamber to recover
  Baseline(Se)   8s        20Hz      shutter closed, accumulate baseline samples
  Open Se        2s        20Hz      se_open(), accumulate in fast_buf + trace
  Close Se       —         —         se_close()
  Compute        —         —         calculate BEP values and ratio

BEP CALCULATION:
  baseline = statistics.mean(all closed-shutter samples)
  Sort open-window samples descending; take top TOP_FRACTION (top 50%).
  peak     = statistics.mean(top 50% of open-window samples)
  BEP      = max(0, peak - baseline)
  RATIONALE: mean of the highest samples avoids transient spikes (from shutter
  opening) while still capturing peak flux. The mean is more stable than max().
  BUG HISTORY: Old code had pressures[top_n:] (selected bottom half — wrong index).
               Fixed to pressures[:top_n] (first elements of descending sort = highest).

class BEPTrace:
  Full annotated timeline for one source measurement (In or Se).
  Used by the fast trace plot in the GUI to show annotations.
  Fields:
    source:          "In" or "Se"
    samples:         List[(t_rel_s, pressure_Torr)] — all samples from baseline start (t=0)
    baseline_end_t:  t_rel when baseline phase ended
    open_start_t:    t_rel when shutter opened
    open_end_t:      t_rel when shutter closed
    baseline_val:    mean of all baseline samples (Torr)
    peak_val:        mean of top TOP_FRACTION open-window samples (Torr)
    bep_val:         peak_val − baseline_val (Torr)
    top_samples:     List[(t_rel, pressure)] — open-window samples in the top fraction

class BEPRecord:
  source, temp_c, baseline (mean_baseline), peak (mean_top_fraction), bep, timestamp

CSV OUTPUT (bep_log.csv — appended each run):
  Columns: Timestamp, Source, Temperature_C, Baseline_Torr, Peak_Torr, BEP_Torr

TEMPERATURES:
  Se temp: read from heat3.ch1_read_process_value() at time of Se measurement
  In temp: live from indium.ch1_read_process_value() if EPC3004 connected; else
           falls back to INDIUM_TEMP_C = 744.0°C (constant, for backward compat)
  BEP tab label (bep_itl): shows "In: X.X°C (live)" when EPC3004 active, else "In: 744°C (fixed)"
  BEPManager.indium attribute (set by _resolve): None | EPC3004 | EPC3004Sim

ATTRIBUTES SET AFTER MEASUREMENT:
  self.last_in_bep, self.last_se_bep, self.se_in_ratio
  self.trace_in:  BEPTrace — full annotated In trace (baseline + open window)
  self.trace_se:  BEPTrace — full annotated Se trace (baseline + open window)
  self.fast_buf:  [(t_rel_to_open, pressure)] open-window samples only (backward compat)

FAST TRACE PLOT (⚡ Fast Trace tab in BEP tab):
  Both In (orange) and Se (purple) traces shown simultaneously on same time axis.
  Each trace starts at t=0 (baseline start for that source).
  Visual annotations per source:
    · Continuous line:    all samples (baseline phase + open window)
    · Shaded band:        open-window time region (LinearRegionItem, semi-transparent)
    · White-outlined dots: top-fraction samples used in BEP mean (scatter overlay)
    · Dashed horiz line:  baseline pressure level
    · Solid horiz line:   baseline + BEP = accepted flux level
  Plot items: _bft_in/_bft_se (lines), _bft_in_top/_bft_se_top (scatter),
              _bft_in_bl/_bft_se_bl (baseline lines), _bft_in_bep/_bft_se_bep (BEP lines),
              _bft_in_rgn/_bft_se_rgn (region items, added/removed dynamically).
  Updated in gui_app._update_fast_trace() called from _bep_plots() → _bep_done().

CALLBACKS:
  self.on_status   = callable(str)   → logged in GUI
  self.on_state    = callable(str)   → updates state label + enable/disable buttons
  self.on_progress = callable(float) → 0..1, updates progress bar
  self.on_complete = callable()      → called when full In+Se sequence completes

THREAD SAFETY RULES:
  ✓ All serial I/O in background threads (Poller, RecipeLogger, RecipeEngine, BEP)
  ✓ DataLogger.feed() is called from Poller thread; guarded by self._lock
  ✓ Snap dict for thread→GUI data handoff (read by _vals on 100ms timer)
  ✓ PlotWorker emits data_ready signal; slot _on_plot_data runs on main thread
  ✓ _RecipeBridge pyqtSignals for recipe engine → GUI (step, status, state)
      pyqtSignal emitted from any thread → always queued to receiver's event loop
      DO NOT use QTimer.singleShot(0, fn) from plain Python threads — unreliable on
      Windows PyQt5 (no Qt event loop on background threads). Use pyqtSignal instead.
  ✗ Never call self._log() from bg thread directly
  ✗ Never call Qt widget methods from bg thread (except emit() on signals)
  ✗ DataLogger.feed() must NOT be called from main thread (it may block on _lock)

DEVICE METHOD RETURN TYPES:
  Single reads (ch1_read_process_value etc.): Optional[float] — None on error
  Command sequences (apply_setpoint, go_operate, go_standby): {"ok": bool, "message": str}
  Connection: bool — raises ConnectionError on failure

RECIPE PARAM CONVENTIONS:
  Param1 for SET_TEMP/RAMP_TEMP/WAIT_TEMP/HEATER_ON/OFF: string like "Selenium (CH1)"
  Param1 for OPEN_SHUTTER/CLOSE_SHUTTER: "In", "Se", or "Both"
  Param1 for WAIT_TIME: float (seconds)
  Param1 for WAIT_PRESSURE: float (Torr target)
  Param1 for GOTO: int (target step NUMBER, not index)

  Param2 for SET_TEMP: float (°C) when Param1 is channel name
  Param2 for RAMP_TEMP: float (°C/min — device-internal ramp rate to set)
  Param2 for WAIT_TEMP: float (tolerance °C, default 2.5)

MOUSE WHEEL NEVER CHANGES INPUTS (wheel_guard.py, 2026-10-06, user request):
  Scrolling past a spin box / dropdown / slider used to change its value. Every entry
  point calls wheel_guard.install(app) right after apply_dark_theme(app) — main.py,
  recipe_editor.py, rheed_app.py. ONE app-wide event filter: wheel events on
  QAbstractSpinBox / QComboBox / QSlider are swallowed and a copy is sent to the
  viewport of the nearest enclosing QAbstractScrollArea (scroll area, table, list), so
  the page/table still scrolls. Values change only by typing, arrows, keyboard or the

  Gotcha found while testing: re-sending the wheel event to the PARENT widget does not
  scroll — Qt propagates only spontaneous (hardware) wheel events up the parent chain.
  wheel_guard.py imports PyQt5 only, so the lean Recipe Editor exe stays OpenCV-free.

SECTION 15: PERFORMANCE TUNING
================================================================================

TARGET: 4 Hz data visible in GUI plots and labels.

BOTTLENECKS IDENTIFIED AND FIXED (May 2026):

  Round 1 — Hardware serial fixes:
  1. HEAT3 _transact() sleep: 40ms → 10ms      (×8 reads saves ~240ms/cycle)
  2. HEAT3 serial timeout: 1.0s → 0.25s        (miss costs 0.25s not 1.0s)
  3. HEAT3 read(max(expected,8)) → read(expected)  (7-byte response no longer
                                                  waits 250ms for phantom 8th byte)
  4. HEAT3 poll_all() added: 8 reads → 3        (~4× fewer round-trips)
  5. Poller uses poll_all() when available       (HEAT3Sim uses individual reads)
  6. BRAX readline() → read_until(b'\r')        (21ms instead of 250ms per read)
  7. BRAX command sleep: 60ms → 20ms            (saves 40ms per read cycle)
  8. BRAX serial timeout: 1.0s → 0.25s

  Round 2 — Software pipeline fixes:
  9.  DataLogger poll thread eliminated; Poller.feed() is single read path
      → removes serial port contention; plot rate = Poller rate
  10. Default poll interval: 1.0s → 0.25s      (min 0.10s in Settings)
  11. Poller.interval now correctly applied at startup (was always 1.0s)
  12. PlotWorker QThread sleep: 250ms → 100ms  (detects new data faster)
  13. Labels timer: 150ms → 100ms              (10 Hz label refresh)
  14. rec_log sync timer: 200ms → 100ms
  15. Rolling window filter in PlotWorker      (setData only over visible range)
  16. Absolute timestamps + DateAxisItem       (correct wall-clock x-axis)

ACHIEVED RATES (with HEAT3 on COM12 + BRAX on COM11, 19200 baud):
  Hardware read time: ~55–70ms per poller cycle (poll_all + BRAX read_until)
  At 0.25s interval  → ~4 Hz data refresh
  Labels             → 10 Hz (100ms timer reading Snap)
  Plot               → ~4 Hz (PlotWorker emits on each new Poller cycle)
  Buffer→plot latency: ~50ms (PlotWorker 100ms tick)

REMAINING HEADROOM:
  At 19200 baud, a 9-byte Modbus read takes ~4ms at hardware level.
  The 10ms inter-transaction sleep is the dominant cost per HEAT3 register.
  Reducing to 0.15s poll interval is feasible if hardware stays stable.
  Below 0.1s risks serial collisions — not recommended.

PURPOSE: Track liquid nitrogen level for the deposition system's LN2 dewar.

DATA SOURCE: Air Products APDirect portal

  read only through a redaction script that blanked every password/token/
  cookie value before any of it reached the assistant — see "HAR HANDLING"
  below. apdirect.airproducts.com is an Angular SPA; the reading is not in
  static HTML, it comes from a JSON API called after login. STATUS: scraper
  IS implemented (devices/ln2_monitor.py, _do_fetch()). Confirmed flow:
    1. GET  account.airproducts.com/login?ReturnUrl=.../Tanks/
       -> scrape __RequestVerificationToken hidden input from the HTML.

       cased variants — the real form posts both), __RequestVerificationToken.
       Success = 302 off the login page. Session auth is cookie-based
       (requests.Session() persists cookies automatically; no bearer token).
    3. GET  apdirect.airproducts.com/Tanks/API/v1/ShipToList
       -> JSON: list of ship-tos, each with logicalAssets[] containing
          logicalAssetId, lastReading{value,dateTime,uom}, fullValue,
          fullUOM, logicalChannels[{logicalChannelId}]. This alone gives
          the current reading AND the tank's true full-scale value —
          tank 52228's confirmed fullValue is 46 (unit "IN"), NOT the
          120 originally guessed before the HAR was captured.
    4. GET  apdirect.airproducts.com/Tanks/API/v1/GetEquipmentReadings
          ?logicalChannelId=<id>&from=<iso>&to=<iso>&companyKey=<..>&
           countryCode=<..>&shipToType=<..>

          backfill up to BACKFILL_DAYS (30) of trend data in one call
          instead of waiting on twice-daily polling to fill the plot.
          _merge_history() dedups by timestamp so repeated backfills
          (every scheduled check) don't re-append the same rows forever.
  Real reading confirmed via the HAR (2026-08-12T15:00 local): tank 52228
  was at 4 in of 46 in full scale — i.e. genuinely near-empty at capture
  time, well under LOW_LEVEL_IN (20).
  fetch() still fails safely at any step (bad credentials, page layout
  change, network error, tank not found in ShipToList) — the GUI falls
  back to its stale ("no recent reading") yellow state rather than crashing
  or fabricating a value.

  HAR HANDLING (how the flow above was learned without exposing the
  password): the user supplied apdirect.airproducts.com.har directly in
  their project folder. It was never opened with a general-purpose file
  read. Instead, a one-off script (devices/ln2_monitor.py's flow was
  reverse-engineered from a REDACTED summary) parsed the HAR and blanked
  any JSON key / form field / header matching password|pwd|secret|token|

  summary was ever read. A follow-up grep for "password"/"pwd" on the

  it was read. The raw .har file itself still contains the real plaintext
  password (HAR captures raw POST bodies) and was flagged to the user as
  a standalone risk — see the 2026-08-12 changelog entry for the outcome.

CREDENTIALS — ENCRYPTED, NEVER IN CHAT/CODE/LOGS:
  Storage: secrets/ln2_creds.dat (gitignored), Windows DPAPI-encrypted
    (ctypes calls to CryptProtectData/CryptUnprotectData — no extra
    dependency). DPAPI ties the ciphertext to the current Windows user
    account + machine; it cannot be decrypted elsewhere.
  Setup: tools/setup_ln2_credentials.py — run manually by the user in their
    own interactive terminal (getpass hidden input). Never run through
    Claude/automation — that is what keeps the plaintext password from ever
    appearing in a transcript or log. Re-run it any time to rotate creds.
  Runtime: LN2Monitor._load_credentials() decrypts to memory only for the
    duration of one fetch() call; no method returns, logs, or prints the
    plaintext username/password.

LN2Reading dataclass: timestamp (unix float), level_in (float, inches),
  raw (optional dict for future fields once the JSON shape is known).

LN2Monitor API (devices/ln2_monitor.py):
  credentials_configured() -> bool
  fetch() -> LN2Reading|None      blocking network I/O — call from a bg thread only.
                                  Re-entrancy-guarded (_fetch_lock) — an overlapping
                                  call is a safe no-op, not queued or errored.
                                  Updates last_reading/last_attempt_ok/last_error,
                                  merges successful reads (+ any backfilled history)
                                  into logs/ln2_history.csv via _merge_history() (dedups
                                  by timestamp), and invokes on_reading(reading|None, ok).
  history(hours=None) -> (t_list, level_list)   absolute Unix timestamps, from CSV
  is_stale(stale_hours=STALE_HOURS) -> bool     True if no successful reading within window
  is_low(low_in=LOW_LEVEL_IN) -> bool
  last_read_str() -> str          "never" or "YYYY-MM-DD HH:MM:SS"
  full_scale_for(reading=None, default=FULL_SCALE_IN) -> float
                                  Prefers the live fullValue from reading.raw (set by
                                  _do_fetch() from the ShipToList API response) over the
                                  FULL_SCALE_IN fallback constant. GUI calls this instead
                                  of using FULL_SCALE_IN directly, so the fill-bar 100%
                                  reference is always the tank's real full-scale value
                                  once at least one live reading has been fetched.
  start_scheduler() / stop_scheduler()   background thread, checks CHECK_TIMES daily
                                  (default 08:00 / 20:00 local) + one catch-up fetch
                                  on startup if the loaded history is already stale.
  on_reading: callable(reading|None, ok: bool)|None
                                  invoked from whichever thread performed the fetch
                                  (scheduler thread or manual-refresh thread) — GUI
                                  MUST bridge to the main thread via pyqtSignal
                                  (see _LN2Bridge in gui_app.py; BUG 7/20 pattern —
                                  QTimer.singleShot from a plain thread is unreliable).

CONSTANTS (devices/ln2_monitor.py, top of file):
  CHECK_TIMES   = [08:00, 20:00]   automatic scheduled check times (local time)
  STALE_HOURS   = 18.0             dewar shown yellow past this many hours since last read
  LOW_LEVEL_IN  = 20.0             dewar shown red at/below this level (inches)
  FULL_SCALE_IN = 46.0             fallback fill-bar 100% reference (= tank 52228's
                                    confirmed fullValue from the ShipToList API); only
                                    used when full_scale_for() has no live reading yet

SCHEDULING MODE: in-app only (QTimer/threading inside the running GUI process).
  Twice-daily checks only happen while VacDepositionControl is open — there is
  no Windows Scheduled Task. If the app is closed at a scheduled check time,
  that check is simply skipped until the next app launch (startup catch-up
  fetch) or the next scheduled time while running. (Chosen deliberately over
  a Task Scheduler-based always-on checker — 2026-08-12.)

GUI INTEGRATION (gui_app.py):

BUILD GOTCHAS (Anaconda + PyInstaller — all handled inside recipe_editor.spec):
  1. Anaconda ships several stdlib extension modules linked against DLLs in
     <sys.prefix>/Library/bin, which PyInstaller does NOT search. Without them the exe
     builds cleanly and then dies on launch with "DLL load failed while importing
     pyexpat" / "_ctypes" / "QtCore". The spec globs Library/bin for
     libexpat*, ffi*, sqlite3*, libbz2*, liblzma* and the three conda-renamed Qt libs
     (Qt5Core_conda.dll / Qt5Gui_conda.dll / Qt5Widgets_conda.dll).
     Guarded by os.path.isdir() so a plain python.org build is unaffected.
     Do NOT bulk-add every *_conda.dll: that set is ~170 MB and includes a 112 MB
     unused WebEngine library.
  2. pyqtgraph's PyInstaller hook collects all its submodules, including optional
     exporters that probe for numba/scipy/h5py/matplotlib. In a conda base env those
     exist, so ~190 MB of unrelated packages get pulled in. The spec's excludes list
     kills them (345 MB → 178 MB unzipped).
  3. Smoke-test the built .exe, not just `python recipe_editor.py` — every failure
     above only appears in the frozen binary.

ARCHITECTURE (rheed/ never imports gui_app or devices/ — like recipe_editor):
  camera.py   _FrameSource base: ONE capture thread per source, never raises after start().
                state: IDLE / CONNECTING / CONNECTED / DISCONNECTED (+ .message, .fps,
                .resolution, .dark).
                Open fails / device unplugged (READ_FAIL_LIMIT=15 consecutive bad reads)
                → DISCONNECTED, release, retry every RECONNECT_INTERVAL=2 s, resume alone.
                open() requires an actual first frame (isOpened() accepts phantom devices).
                .dark = frame std < DARK_STD(2.0): no HDMI signal / camera asleep / beam
                off. A FLAG, not a disconnect — a dark screen is a legitimate RHEED state.
              Consumers: latest() → newest Frame (GUI polls), subscribe(maxsize) →
                FrameQueue of every frame; a slow consumer DROPS frames (counted in
                q.dropped) instead of blocking capture.
              Frame(image BGR uint8 — read-only/shared, t=time.time(), index)
              RHEEDCamera(index, backend="dshow", width, height, fps, fourcc=None|MJPG|YUY2)
              SimRHEEDCamera(rpm=10) — synthetic 4-fold surface (render_sim_pattern):
                sharp streak family at 0/90/180/270°, weaker √2-spaced family at 45°…,
                moving diffuse spots off-azimuth, and a sin(φ) specular wobble so the
                true 360° period repeats exactly but the 90° sub-period only nearly
                (like a real wobbling holder). Used for test mode and all tests below.
              list_cameras(max_index=6, skip=()) — probes DSHOW indices (~0.5–1 s each,
                run on a thread); names via optional pygrabber, else "Camera N".
              OPENCV_LOG_LEVEL=ERROR is set before cv2's first import (camera.py) —
                otherwise the 2 s reconnect loop prints a DSHOW warning every retry.
                (cv2.utils.logging does NOT exist in the opencv-python wheels.)
  rotation.py Pure numpy (cv2 only for resize). See ALGORITHM.
  capture.py  save_snapshot(), VideoRecorder (MJPG .avi until stop), RotationCapture.
              Callbacks fire on WORKER threads → GUI bridges via pyqtSignal.
  rheed_tab.py RHEEDTab(QWidget). Polls the source with QTimers (_view_t 50 ms → image,
              _stat_t 250 ms → LED/state/fps/buttons); worker callbacks re-emitted via
              _Bridge pyqtSignals (BUG 7/20 rule — no QTimer.singleShot from threads).
              Display is downsampled 2× above 1600 px wide; captures stay full-res.
              ImageItem.setRect maps the display to FULL-RES pixel coords, so the ROI
              (pg.RectROI, yellow) is read directly in camera pixels.

ROTATION-SYNC ALGORITHM (rotation.analyze_rotation):
  1. Per frame: 128-px-wide grey thumbnail (make_thumb, optional ROI) + quality score.
     Streak ORIENTATION (added 2026-10-06): orientation="auto"|"vertical"|"horizontal".
     Auto (streak_orientation) = the profile direction whose per-frame score has the
     larger coefficient of variation (the right one swings with rotation; the wrong one
     is dominated by the static screen rim / shadow edge). Both CV < 0.03 → vertical.
  2. Subtract the clip's MEAN thumbnail (static shadow edge / glow otherwise make all
     frames look alike), then TEMPORAL HIGH-PASS (added 2026-10-06): subtract a moving
     mean over detrend_s (auto = 1.5×expected_period, else clip/2; 0 = off) — removes
     slow beam/glow drift, which on MVI_2527 dominated the raw correlation. The window
     MUST stay longer than the period: 1 s on the 4-fold sim locked T/4, 20–30 s on
     MVI_2527 locked T/5 (it strips the once-per-rev content that separates T from
     its symmetry sub-period). L2-normalise → correlation matrix C = X·Xᵀ.
  3. Self-similarity vs lag: mean C over all pairs binned by their TIMESTAMP difference
     (bin = median frame interval). Timestamps, not indices → dropped frames are harmless.
  4. Period: search lags ≥ first local minimum (skip the trivial short-lag peak) up to
     0.85×clip; take the EARLIEST local peak ≥ HARMONIC_TOL(0.90)×best peak (otherwise
     2T can beat T on noise — seen in testing at 7.3 rpm), parabolic sub-bin refine.
     expected_period (from the rpm box) narrows the search to ±25 %. If the peak lands
     on the window's upper edge → .warning "clip probably too short for this rpm"
     (lags only reach 0.85 × clip; e.g. 110 s of MVI_2527 at 0.62 rpm read 88.5 s).
     peak < MIN_CONF(0.25) → "no rotation" → keep the top-quality frames instead.
     fold: equal peaks at every k·T/n (n∈6,4,3,2) → reported "n-fold pattern symmetry".
  5. azimuth_i = 360·((t_i−t0) mod T)/T  — RELATIVE to the clip's first frame (no encoder).
  6. Quality = std of the high-passed profile across the streaks (column means for
     vertical streaks, row means for horizontal) = "streak contrast". Binned to 5° (72 bins), circular 1-2-1 smoothing; the top
     n_picks local maxima ≥ 20° apart are kept. Per pick: best frame (max quality
     within ±1 bin) + one frame per revolution within ±1 frame of rotation (members).
  KNOWN LIMIT: a clip SHORTER than one true revolution can only reveal the symmetry
    sub-period (90° on 4-fold) → rpm reads n× high. Without an rpm entered, the result
    carries .warning saying so; the GUI auto-lengthens the clip to ≥2.5 revs when an rpm
    is typed. Real-substrate behaviour (growth drift, wobble, exposure) NOT yet verified.
  VALIDATED (synthetic, 10 % random drops + 4 ms jitter): 3–15 rpm → period error
    ≤0.22 %, picks within ~1–2° of truth; static substrate → "no rotation"; analysis of
    600 frames ≈ 0.06 s.

ROTATIONCAPTURE PIPELINE (capture.py) — "short clip → keep good frames → delete clip":
  RECORD   frames → temp .avi in tempfile.gettempdir() (NOT the OneDrive project folder:
           it would start syncing hundreds of MB) + thumbnail/timestamp per frame in RAM
           (~30 MB for 20 s @ 30 fps). Stall > STALL_TIMEOUT(3 s) = camera lost →
           analyse the partial clip.
  ANALYSE  analyze_rotation(times, thumbs, expected_period=60/rpm, n_picks).
  EXTRACT  one sequential read of the clip: per pick, best frame + float mean of members.
  CLEAN UP temp clip deleted in a finally (moved to clip.avi if keep_video).
  Never raises: any exception → on_done(None, "capture failed: …").
  TEMP CODEC (benchmarked 2026-10-01, opencv 4.10, 1080p):
    MJPG via cv2.CAP_OPENCV_MJPEG (default): ~75 fps encode, 0.42 MB/frame, mean error
      1.6 grey levels (below camera noise). VIDEOWRITER_PROP_QUALITY has NO effect
      (90/95/100 identical output).
    FFV1 lossless (opt-in checkbox): only ~10 fps at 1080p, 2.6 MB/frame → most frames
      DROPPED at full HD. Fine at 720p / low fps.
  OUTPUT logs/rheed/<YYYYMMDD_HHMMSS>_<sample>/
           az1_057.9deg_best.png, az1_057.9deg_avg3.png, …   (angles rel. to clip start)
           rotation_summary.json (period, rpm, confidence, fold, picks, settings, warning)
           frames.csv            (Frame, Unix_Time, Elapsed_s, Azimuth_deg, Quality)
         logs/rheed/snapshots/<stamp>.png     logs/rheed/videos/<stamp>.avi (MJPG)

SPATIAL ANALYSIS (spatial.py — numpy only, requests only for COD):
  Geometry: streak spacing Δ = L·λ/d_row, d_row = spacing of atomic rows ∥ beam.
    hex net a: beam ∥ ⟨11-20⟩ d = a·√3/2, ∥ ⟨1-100⟩ d = a/2 (ratio √3, 30° apart);
    square a: ⟨10⟩ d = a, ⟨11⟩ d = a/√2 (ratio √2, 45°); rect: b, a, ab/√(a²+b²).
    Nets from bulk cells: hex/trig (0001) → a; cubic F (001) square a/√2, (111) hex
    a/√2; cubic P/I (001) a, (111) a√2; tetragonal (001) a; orthorhombic rect a×b.
  λ(keV) relativistic: 12.2643/√(V(1+0.97848e-6·V)) Å. Calibration k = Δ·d (px·Å).
  find_peaks: Gaussian smooth 2 px → minus baseline (rolling MIN over bg width, running
    mean, lifted by the median residual) → local maxima > σ·noise (noise = MAD of the
    raw profile's first difference /√2) → strongest-first min separation → parabolic
    sub-px position, FWHM by half-max interpolation. Peaks with FWHM > bg width are
    DIFFUSE GLOW and dropped — without that, MVI_2527's glow under the spot made 150–300
    px "peaks" and the spacing fit returned 28 px instead of 117 px.
  fit_spacing: seed Δ0 = distance from the (00)/strongest peak to its nearest peak of
    ≥ 30 % its height (or user seed) → integer orders → least squares x = x0 + nΔ (3
    iterations, |residual| ≤ 0.2) → Δ ± σ; peaks at n+½ flagged (×2 reconstruction).
  peak_intensity: mean over ±half_w minus two flanking background windows; per frame.
  azimuth_locked: per revolution, mean over frames within ±tol of the azimuth.
  rotation_normalised: I / median-per-azimuth-bin (72 bins); bins < 20 % of max → NaN.
  oscillation_period: interpolate NaNs, running-mean detrend (2·pmax), Hann FFT,
    parabolic peak in [pmin, pmax].
  cod_lookup(formula): GET https://www.crystallography.net/cod/result?formula=<Hill,
    alphabetical, space-separated>&format=json (no key; fields a b c alpha beta gamma
    sg file title) → dedup → surface_nets(). Materials Project OPTIMADE also answers
    without a key but returns computed primitive (e.g. rhombohedral) cells — not used.
  RESULTS ON MVI_2527 at 3.1 rpm (T = 19.303 s, 6.7 revs): kept azimuths 74/149/244/
    266/359°; 244° and 266° (q 0.82/0.84) give the SAME Δ = 117.3 ± 1.0 px (4 orders:
    rows 518/639/756/871 px; specular spot = 756) → one direction family split ±11°;
    74° has no streaks (diffuse). Azimuth-locked spot intensity rises ~1.2 → 3.8 → back
    over the clip (this is what the 96.5 s "period" was).
  OPEN SOURCE LANDSCAPE (researched 2026-10-06): xRHEED (MIT, xarray toolkit: profiles,
    kx–ky transform, predicted-spot overlay, lattice matching — github.com/
    mkopciuszynski/xrheed); rheedium (MIT, JAX differentiable RHEED simulation from
    CIF + fit-to-experiment — github.com/debangshu-mukherjee/rheedium); RHEEDsim-Python

LIVE INTENSITY TRACKING — RHEED OSCILLATIONS (tracking.py + live_tracking.py, 2026-10-07)
  Roadmap R11 (phase-locked live acquisition) + the live half of R12. User request:
  "record an approximate rpm, track the intensity, only process frames at/near the
  peak to save processing, plot intensity vs time".
  Live panel → group "Intensity tracking — RHEED oscillations" (control column is now a
  QScrollArea) + result tab "📈 Intensity (live)" + CYAN intensity box on the image.
  ROTATING mode:
    1. Approx. rotation (rpm) + Lock length (rev, default 3) → 🔒 Lock rotation:
       RotationLock records THUMBNAILS ONLY (no video, nothing saved) for revs·60/rpm s
       → analyze_rotation(expected_period = 60/rpm, analysis ROI if ticked) →
       LockResult(period_s, t_ref = time.time() of azimuth 0, picks [(az, q)]).
    2. Drag the cyan box onto the specular spot / a streak; pick the direction;
       Window ± (default 6°); Value per pass Peak (max of 3-frame smoothed) / Mean.
    3. ▶ Start: IntensityTracker per frame computes ONLY the predicted azimuth from the
       timestamp; frames outside ±window are skipped untouched; inside → box mean
       (green-channel grey). On leaving the window the pass → ONE point.
       ~3–5 % of frames processed (3.2 % at 3.1 rpm/±6°, 3.6 % at 10 rpm).
    PHASE-LOCKED LOOP (per clean pass): peak time = intensity-weighted centroid of
      the half-maximum run around the max (min-subtracted); err = peak − predicted;
      t_cross = t_pred + 0.6·err; T += 0.3·err (z² − 1.1z + 0.4 → |z| 0.63/rev,
      stable); T clamped to ±15 % of the lock; t_ref RE-ANCHORED at t_cross each pass
      (otherwise a T update swings the phase by revs-since-lock × ΔT: 0.1 % after
      30 revs ≈ 11°). "Clean" = window max−min ≥ 1 % of max (flat window → no steer).
    ACQUISITION: unclean pass or |err| > ½ window → window ×2 (max ±25°, below the
      30°/45° neighbour spacing of 6-/4-fold surfaces); clean & centred → ×0.7 back.
      After a pass, a new one may start only once |phase − az| > 90° (REARM_DEG) —
      without it passes fired 0.2 s apart when the window widened / t_ref moved.
    WHAT FAILED ON THE WAY (don't retry): argmax + parabola peak (noise with 4 frames
      / pass, often on the window edge) + edge "hunting" steps (knocked the phase every
      pass); noise from frame-to-frame diffs as the "clear peak" test (the diffs ARE
      the peak's slope — nothing ever qualified); T from two consecutive peaks only
      (slow after an rpm step); window up to ±45° (pulled to the neighbour direction).
  STATIC mode: every Nth frame's box mean → the classic oscillation trace.
  ⏱ t = 0 = growth start (plot origin; restarts the sim's test oscillation). FFT period
    range (default 0.5–60 s) → oscillation period → ML/s (1 osc = 1 ML assumed).
    Rotating: status warns only periods > 2T are real (one sample per revolution).
  💾 Save CSV… — only on request (QFileDialog, default logs/rheed/tracking/
    <stamp>_<sample>_intensity.csv): '#' header (mode, box, t0, lock T, direction,
    window, end T) + Unix_Time, Time_s, Intensity, Phase_err_deg, Clean_peak.
  Points are POLLED (snapshot(since)) by a 300 ms QTimer — no per-frame signals.

#
#   Diagnostic tool (diagnostics/epc3004_diag.py):
#             New standalone script. Sections A-K cover: raw comms check,
#             slave ID scan (1-8), key register probe with both resolution
#             factors, block scan (regs 0-9 and 271-277), SP write test,
#             Auto/Manual mode check, RS-485 timing sweep (10/30/50ms),
#             baud rate sweep (9600/19200/38400), resolution factor conclusion,
#             writable SP scan across 7 candidate addresses, ramp register scan.
#             Run with GUI closed (exclusive serial port).
#             Usage: python diagnostics/epc3004_diag.py [port] [slave_id] [baud]
#
#   Findings from first successful diagnostic run (COM13, slave 1, 19200):
#
#   1. RESOLUTION_FACTOR = 10 (was 1):
#             PV raw=2000, factor=1 → 2000°C (impossible).
#             PV raw=2000, factor=10 → 200.0°C (Indium standby temp — correct).
#             Fixed: EPC3004.RESOLUTION_FACTOR = 10 in devices/epc3004.py.
#
#   2. R_SP write address corrected 0x0002 → 0x0018:
#             reg 0x0002 (frame addr 2) is the Working Setpoint (read-only).
#             Write to 0x0002 returns Modbus exception FC=0x06 code=2 (Illegal address).
#             reg 0x0018 (frame addr 24) is the writable Target Setpoint 1.
#             Confirmed by write (raw=500) + readback (raw=500) test.
#             Fixed: R_SP = 0x0018; R_SP_RO = 0x0002 added (read-only display alias).
#             apply_setpoint() now writes and reads back from R_SP (0x0018).
#             poll_all() still reads in_sp from R_SP_RO (0x0002) for live
#             working-SP display during ramps.
#
#   3. Ramp rate registers corrected 0x0023/0x0024 → 0x0020/0x0021:
#             Old R_SP_RATE = 0x0023 read 0; R_SP_RATE_U = 0x0024 returned
#             0x8000 sentinel (Eurotherm "not applicable" — parameter does not
#             exist at this address on this firmware).
#             New R_SP_RATE = 0x0020 reads 1000 = 100.0°C/min (×10 encoding).
#             New R_SP_RATE_U = 0x0021 reads 0 = off (ramp currently disabled).
#             Fixed: R_SP_RATE = 0x0020, R_SP_RATE_U = 0x0021 in epc3004.py.
#             NOTE: write access to 0x0020/0x0021 not yet tested — if
#             write_ramp_rate() fails in the GUI, use iTools to locate the
#             correct writable ramp address and update accordingly.
